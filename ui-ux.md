# UI/UX DiceBound

Документ описывает интерфейс DiceBound MVP: экраны, маршруты, компоненты,
состояния элементов, тексты и правила адаптивности.
Он нужен frontend-команде, чтобы реализовать интерфейс по утверждённому
дизайну без обращения к макетам за недостающими деталями.
Scope продукта описан в [DiceBound MVP](./mvp-scope.md),
HTTP API — в [технических контрактах](./technical-contracts.md),
формат схемы — в [SheetSchema and Character Data](./data-model/sheet-schema.md).

> Status: Active

## Источник дизайна

Макеты находятся на холсте [DiceBound — MVP дизайн][figma].
При расхождении этого документа и холста верен холст.
Формат `Sheet Schema` и API задают контрактные документы:
если холст им противоречит, исправляется холст.
Расхождение дизайна с [DiceBound MVP](./mvp-scope.md) исправляется в дизайне.

Холст разделён на четыре страницы.

- «Основной дизайн» — экраны desktop 1280 px, телефон 390 px, планшет 768 px,
  справочные доски `FieldKit`, `States`, `Responsive`.
- «Состояния» — доски `State-*`: варианты экранов после действий
  пользователя и ошибок.
- «UI-kit» — `UIKit-Foundations`, `UIKit-Controls`, `UIKit-Feedback`,
  `UIKit-Icons`, `UIKit-States`.
  Доска `UIKit-States` закрывает pressed, загрузку, недоступные поля, движение
  и фиксирует одно значение там, где другие доски расходились.
- «Вайрфреймы» — доски `WF-*`, исторические.
  Для реализации не используются.

Доски страницы «Основной дизайн» сгруппированы по рядам.

- Вход и список персонажей — `Main`, `Characters`, `CharactersEmpty`,
  `DeleteConfirm`.
- Создание персонажа и динамический лист — `Create`, `SheetDnD`, `SheetCoC`.
- История версий и восстановление — `History`, `Version`, `RestoreConfirm`.
- Доступ `VIEW` / `EDIT` — `Access`, `ShareAdd`, `SheetView`.
- Импорт НРИ и профиль — `Import`, `ImportError`, `Profile`, `Systems`.
- `EDIT`-копия, renderer и системные состояния — `SheetCopy`, `FieldKit`,
  `States`.
- Адаптивность, телефон — `Responsive`, `MLogin`, `MCharacters`, `MCreate`,
  `MSheetDnD`, `MHistory`, `MVersion`, `MAccess`, `MShareAdd`, `MImport`,
  `MSystems`.
- Адаптивность, планшет — `TCharacters`, `TSheetDnD`, `TCreate`, `TAccess`,
  `TImport`.

## Принципы UI/UX

**Лист не рисуется под НРИ.**
Любой лист собирает один компонент `Dynamic Sheet Renderer` из `Sheet Schema`
и данных персонажа.
D&D 5e, Call of Cthulhu и импортированная Custom System на холсте построены из
одних и тех же шести типов полей.

**Один renderer для всех режимов.**
Редактирование, просмотр старой версии, лист получателя `VIEW` и предпросмотр
импорта используют тот же renderer.
Режим read-only включается флагом, а не отдельным компонентом.

**Необратимое действие называет последствие.**
Восстановление версии, выдача `EDIT`, удаление персонажа, удаление системы и
отзыв `VIEW` требуют подтверждения.
Кнопка подтверждения описывает результат, например
«Восстановить и удалить 3 версии», а не «ОК».

**Вычисляемое видно сразу.**
Фиолетовый используется для `calculated`-полей, формул, фокуса и
информационных баннеров.
Пользователь отличает вычисляемое значение от редактируемого без чтения
подписей.

**Интерфейс не раскрывает чужие данные.**
Ошибки выдачи доступа, регистрации и недоступного персонажа не сообщают,
существует ли аккаунт или чужой персонаж.

**В интерфейсе нет функций вне MVP.**
Функции, исключённые из MVP, не появляются даже как заглушка «скоро».

## Визуальное направление

Интерфейс использует тёмную тему со спокойной «настольной» атмосферой.
Crimson — акцент действий.
Фиолетовый — маркер вычисляемых значений и фокуса.
Зелёный обозначает успешное состояние.

### Метки игровых систем

Метка — квадрат с моноширинной аббревиатурой.
Размер — 38 px в списках, 52 px в шапке листа, 40 px в карточках телефона,
44 px в шапке листа на телефоне.

- D&D 5e, `D&D` — crimson: фон `rgba(176,42,64,.16)`, граница
  `rgba(234,106,126,.36)`, текст `#ea6a7e`.
- Call of Cthulhu, `CoC` — зелёный: фон `rgba(109,191,149,.10)`, граница
  `rgba(109,191,149,.30)`, текст `#8fd4b0`.
- Импортированная система — фиолетовый: фон `rgba(154,143,230,.13)`,
  граница `rgba(154,143,230,.34)`, текст `#b3aaf0`.
  Аббревиатура — первые буквы слов названия, например `CS`, `SF`.

У персонажа с доступом `VIEW` граница метки пунктирная.

### Подсветка JSON

- Ключи — `#9dbbe8`.
- Строки — `#8fd4b0`.
- Числа и `true` / `false` / `null` — `#e6c07b`.
- Значение `formula` — `#c9c2f7`.
- Скобки, запятые, двоеточия — `#6f6c7e`.
- Недопустимый текст — `#ea6a7e`.
- Значение с ошибкой проверки — волнистое подчёркивание `#ea6a7e`,
  смещение 3 px.
- Строка с ошибкой — фон `rgba(176,42,64,.16)`, номер строки `#ea6a7e`.
- Номера строк — `#4a4a60`, выравнивание вправо.

## Layout

### Каркас приложения

Рабочая ширина макетов — 1280 px.
Все экраны после входа используют один каркас.

- Боковая панель
  - Ширина 224 px, фон `#121218`, граница справа `#2a2a37`,
    отступы 20 px сверху и снизу, 14 px по бокам.
  - Липкая (`position: sticky`): при прокрутке контента остаётся на месте.
  - Сверху логотип, горизонтальный вариант высотой 28 px, ссылка на
    `/characters`.
  - Пункты «Персонажи», «Импорт системы», «Профиль»: высота 40 px,
    скругление 9 px, иконка 16 px, промежуток между пунктами 2 px.
- Верхняя панель
  - Высота 56 px, граница снизу `#2a2a37`, отступы 32 px по бокам.
  - Слева хлебные крошки, справа кнопка аккаунта: высота 36 px,
    полностью скруглённая, иконка `user` и почта, ведёт на `/profile`.
- Контент
  - Отступы 28 px сверху, 36 px по бокам, 40 px снизу.
  - Вертикальный шаг между блоками 22 px.
- Панель сохранения на листе
  - Закреплена внизу окна поверх контента, от правого края боковой панели до
    правого края окна.
  - Высота 68 px в одну строку, отступы 36 px по бокам, фон
    `rgba(18,18,24,.96)`, граница сверху `#2a2a37`.
  - Когда статус, текст ошибки и кнопки не помещаются в одну строку (при
    ошибках примерно до 1100 px окна), кнопки переносятся на вторую строку
    справа, высота панели растёт до 87 px.
  - На странице с панелью нижний отступ контента 108 px, чтобы панель не
    перекрывала последнюю секцию.

Экран `/login` каркас не использует: сверху шапка с логотипом слева, ниже по
центру слоган, подзаголовок и карточка формы шириной 400 px.

### Страница персонажа

Шапка содержит метку системы 52 px, имя персонажа, чип системы, название листа
«Лист: {название}», дату «Изменён {дата}» и «Версия N» обычным текстом, не
чипом.
На телефоне на листе даты «Изменён» нет (`MSheetDnD`), на странице версии она
есть (`MVersion`).
У `EDIT`-копии рядом с именем чип «копия», у получателя `VIEW` —
«Владелец: {почта}» вместо номера версии.
Под шапкой расположены вкладки «Лист | История | Доступ».
Под вкладками идут карточки секций листа.

## Маршруты и навигация

Боковая панель содержит три пункта: «Персонажи», «Импорт системы», «Профиль».
Активный пункт определяется первым сегментом маршрута:
`/characters*` — «Персонажи», `/systems*` — «Импорт системы»,
`/profile` — «Профиль».
Страница `/systems` отдельного пункта не имеет.

| Маршрут | Доступ | Хлебные крошки |
| --- | --- | --- |
| `/login` | без сессии | нет |
| `/characters` | вошедший | Персонажи |
| `/characters/new` | вошедший | Персонажи / Новый персонаж |
| `/characters/:id` | владелец, `VIEW` | Персонажи / {имя} |
| `/characters/:id/versions/:n` | владелец, `VIEW` | … / История / Версия N |
| `/systems/import` | вошедший | Импорт системы |
| `/systems` | вошедший | Импорт системы / Игровые системы |
| `/profile` | вошедший | Профиль |

Вкладки персонажа добавляют сегмент в крошки:
«Персонажи / {имя} / История», «Персонажи / {имя} / Доступ».
Вкладка «Лист» дополнительного сегмента не добавляет.
Все сегменты, кроме последнего, — ссылки.
Вкладки персонажа меняют состояние страницы `/characters/:id`;
отдельного маршрута у вкладки нет.

Версия `/characters/:id/versions/:n` доступна владельцу и получателю `VIEW`,
которому владелец открыл историю.
Без открытой истории маршрут ведёт на экран
«Персонаж не найден или доступ закрыт».

```mermaid
flowchart LR
    Login["/login"] -->|вход| Characters["/characters"]
    Login -->|регистрация| Empty["/characters, пустой список"]
    Characters --> Create["/characters/new"]
    Characters --> Character["/characters/:id"]
    Create -->|«Создать персонажа»| Character
    Create -->|«Управлять системами»| Systems["/systems"]
    Create -->|«Импортировать из JSON»| Import["/systems/import"]
    Import -->|«Мои игровые системы»| Systems
    Import -->|«Импортировать систему»| Create
    Systems -->|«Импортировать из JSON»| Import
    Character -->|История → «Открыть»| Version["/characters/:id/versions/:n"]
    Version -->|«К истории», восстановление| Character
    Profile["/profile"] -->|«Выйти»| Login
```

Пункты боковой панели и кнопка аккаунта доступны с любого экрана после входа,
поэтому на схеме не показаны.

### Переходы и сессия

- Защищённый маршрут без сессии ведёт на `/login`.
  Адрес исходной страницы передаётся на `/login`, после входа пользователь
  возвращается на него.
- Вход без исходной страницы ведёт на `/characters`.
- Регистрация создаёт сессию и ведёт на `/characters` с пустым списком.
- `/login` при действующей сессии ведёт на `/characters`.
- «Выйти» завершает сессию и ведёт на `/login`.
- Создание персонажа ведёт на `/characters/:id` нового персонажа.
- Импорт системы ведёт на `/characters/new`, новая система уже в списке шага 1.
- Восстановление версии ведёт на вкладку «Лист» восстановленного персонажа.
- Выдача `EDIT` оставляет владельца на вкладке «Доступ».
- Удаление персонажа ведёт на `/characters`.
- Неизвестный маршрут показывает экран
  «Персонаж не найден или доступ закрыт» с кнопкой «К списку персонажей».

На телефоне хлебные крошки скрыты.
На вложенных экранах слева в верхней панели кнопка «назад» 44 px:
с листа, истории и доступа — к списку персонажей, с импорта — назад по истории
браузера.

## Экраны

Каждый экран с данными также обрабатывает загрузку, ошибку загрузки,
404 и истёкшую сессию, см. [Системные состояния](#системные-состояния).

### Вход и регистрация

Маршрут `/login`, доски `Main`, `MLogin`, `State-Main`,
`State-MainReg`.

Карточка формы содержит переключатель «Вход | Регистрация».
Переключатель — контейнер `#1e1e28` со скруглением 11 px и отступом 4 px,
активная вкладка — фон `#282836`, неактивная — прозрачная, текст `#8b8899`.

- Вход: «Почта», «Пароль», primary-кнопка «Войти» на всю ширину.
- Регистрация: «Почта», «Пароль» с подсказкой «Не короче 8 символов»,
  «Повторите пароль», primary-кнопка «Создать аккаунт» на всю ширину.

Плейсхолдер почты — `you@example.com`.
Ошибки проверяются при отправке формы, поля не очищаются.

| Ситуация | Где | Текст |
| --- | --- | --- |
| Неверная почта или пароль | над кнопкой | Неверная почта или пароль |
| Неверный формат | под «Почта» | Введите почту в формате `name@example.com` |
| Почта занята | под «Почта» | см. ниже |
| Пароль короче 8 | под «Пароль» | Не короче 8 символов |
| Пароли не совпадают | под повтором | Пароли не совпадают |

Почта занята: «Не удалось создать аккаунт с этой почтой.
Если он у вас уже есть — войдите».
Текст не утверждает, что аккаунт существует.
При ошибке длины пароля подсказка под полем становится ошибкой.
Ошибка входа выводится блоком с `role="alert"`, остальные — под полем.

Фон страницы — радиальный градиент от верхнего края по центру:
`radial-gradient(60% 50% at 50% 0%, rgba(176,42,64,.10), transparent 70%)`
на `#0e0e12`.
На телефоне эллипс `90% 40%` и непрозрачность `.12`.

На телефоне (`MLogin`) каркаса нет: шапка 56 px с логотипом слева, под ней

выданные доступы…»

### Импорт системы

Маршрут `/systems/import`, доски `Import`, `ImportError`, `MImport`, `TImport`,
`State-Import`, `State-MImport`.

Заголовок «Импорт игровой системы», подзаголовок «Опишите лист в формате Sheet
Schema — система появится в списке при создании персонажа», справа кнопка
«Мои игровые системы».

Слева форма, справа результат проверки.

- Поля «Название системы» и «Название листа» в две колонки.
- «JSON-схема» — редактор высотой 536 px с подсветкой и номерами строк,
  справа над ним ghost-кнопка «Выбрать .json файл».
- Под редактором статус синтаксиса: зелёная точка и «JSON корректен ·
  N строк» или красная точка и «Ошибка синтаксиса JSON · строка N».
  Статус обновляется при каждом изменении текста.
- Кнопки «Проверить схему» и primary «Импортировать систему».

Результат проверки справа:

- Схема не проверялась или есть синтаксическая ошибка — «Схему нельзя
  проверить», «Исправьте синтаксис JSON — предпросмотр появится после проверки
  схемы.»
- Схема корректна — зелёный баннер «Схема корректна», сводка
  «N секции · N полей · N формула» и «Предпросмотр листа» с чипом
  «тот же renderer».
- Найдены ошибки — заголовок «Найдено N ошибки», «Исправьте JSON и проверьте
  снова», список «Ошибки», под ним «Предпросмотр листа появится, когда схема
  пройдёт проверку».

Строка ошибки содержит JSON-путь crimson моноширинным шрифтом,
«· строка N» и текст ошибки.
Строки с ошибками подсвечены в редакторе.
Тексты ошибок приходят от сервера, примеры с холста:

- `sections[0].fields[1].type` — «Неизвестный тип «slider». Допустимо: text,
  number, select, checkbox, resource, calculated.»
- `sections[1].fields[1].formula` — «Функция «pow» не поддерживается.
  Допустимо: floor, ceil, round, min, max.»
- `sections[1].fields[1].formula` — «Поле «agility» не найдено в схеме.»

«Импортировать систему» доступна только после успешной проверки текущего
текста.
Изменение текста сбрасывает результат проверки.

| Ситуация | Где | Текст |
| --- | --- | --- |
| Пустое название системы | под полем | Введите название системы |
| Пустое название листа | под полем | Введите название листа |
| Файл не `.json` или не читается | баннер над редактором | см. ниже |

Баннер файла — crimson, `role="alert"`: «Не удалось прочитать файл «{имя}»» и
«Выберите файл с расширением .json. Текст в редакторе не изменён.»
Корректный файл заменяет текст редактора.

## Состояния элементов

Значения взяты с досок `UIKit-Controls`, `UIKit-Feedback`, `UIKit-States`,
`FieldKit` и экранов.

### Общие правила

- Фокус показывается по `:focus-visible` у всех интерактивных элементов:
  обводка 2 px `#9a8fe6`, смещение 2 px.
- Курсор у кнопок и ссылок — `pointer`, у недоступных — `not-allowed`,
  у кнопки в загрузке — `progress`.
- Hover и pressed не меняют размер и положение элемента.
- Hover не применяется на устройствах без наведения.
- Смысл состояния не передаётся одним цветом:
  ошибка — цвет и текст, `VIEW` — пунктир, иконка глаза и чип.

### Движение

| Токен | Значение | Где |
| --- | --- | --- |
| `motion/fast` | `120ms ease-out` | Цвета при hover и pressed |
| `motion/base` | `180ms cubic-bezier(.2,0,0,1)` | Модальное окно, баннер |
| `motion/slow` | `240ms cubic-bezier(.2,0,0,1)` | Меню и лист снизу |
| `motion/exit` | `140ms ease-in` | Закрытие окна, меню, листа |
| `motion/spin` | `800ms linear infinite` | Вращение `loader` |

- Модальное окно: затемнение `opacity` 0 → 1, окно `opacity` 0 → 1 и
  `scale(.98)` → 1.
- Меню телефона: `translateX(-100%)` → 0.
- Лист снизу: `translateY(100%)` → 0.
- Баннер и уведомление появляются через `opacity`.
- Фокус, ошибки, пересчёт `calculated` и полоса `resource` меняются сразу.
- Скелет загрузки статичен.
- При `prefers-reduced-motion: reduce` все переходы 0 ms,
  `loader` не вращается.

## Dynamic Character Sheet

`Dynamic Sheet Renderer` выбирает компонент поля по `field.type`,
а не по игровой системе.
Интерфейс не содержит ветвлений вида «если D&D — показать такой-то лист».
Импорт схемы не может добавить новый тип поля.
Справочник компонентов находится на доске `FieldKit`.
Формат схемы описан в [SheetSchema and Character Data](./data-model/sheet-schema.md).

### Секции и сетка

`section` — не поле, а карточка с заголовком `label`.
Заголовок — Geist Mono 12 px `#8b8899`, отступ до полей 14 px, на телефоне
12 px.
Renderer выводит поля строго в порядке массива `fields`,
заполняя сетку в 4 колонки слева направо и сверху вниз.
Каждое поле занимает одну колонку, `resource` — 2 колонки.
Ширины поля в `Sheet Schema` нет, поэтому другие поля, например «Имя», шире
одной колонки не бывают.
`number` и следующее за ним `calculated`-поле, формула которого ссылается на
это число, показываются парой «значение | модификатор».
Пара — плашка `#15151c` с границей `#23232e` и скруглением 12 px.

Колонки пар определяются шириной секции, а не окна.

| Ширина секции | Пары |
| --- | --- |
| от 924 px | 3 колонки |
| 612–923 px | 2 колонки |
| 300–611 px | каждая пара — строка на всю ширину |
| уже 300 px | столбик: подпись, счётчик, модификатор, формула |

В режиме чтения от 612 px секции число и формула стоят в одной строке внутри
плашки модификатора, её высота 40 px, как у поля числа.
В режиме правки плашка модификатора 32 px, формула стоит под ней.
На секции уже 612 px формула стоит под плашкой в обоих режимах и начинается
со знака «ƒ»: подпись модификатора там скрыта.

При окне 1280 px секция даёт 3 колонки пар.
Из-за боковой панели окно 1024–1180 px даёт 2 колонки пар, а не 3; так и
задумано, отдельной доски нет.

### Типы полей

| `type` | Редактирование | Ошибка | Read-only |
| --- | --- | --- | --- |
| `text` | поле ввода | `required`, `maxLength` | плашка |
| `number` | поле; в паре — счётчик − / + | вне `min–max` | плашка, моно |
| `select` | список `options` | не из `options` | плашка |
| `checkbox` | строка с квадратом | не бывает | серый квадрат |
| `resource` | текущее / макс. | см. ниже | «21 / 28» |
| `calculated` | не редактируется | ошибка расчёта | значение, формула |

- `text`
  - Пустое обязательное поле: «Обязательное поле».
  - Длиннее `maxLength`: «Не длиннее {maxLength} символов».
- `number`
  - Поле Geist Mono, диапазон `min–max` серым внутри поля справа.
    Если задана только одна граница, диапазон внутри поля не показывается.
  - Кнопки − / + с шагом 1 только у пары «характеристика + модификатор».
    Одиночное число (уровень, AC, навыки CoC) — поле с диапазоном внутри, без
    кнопок.
  - Допускаются дробные числа: разделитель — точка или запятая, в данных
    хранится число (`1,5` и `1.5` — одно значение).
    Минус разрешён, если `min` меньше 0 или `min` не задан.
  - Ошибка: «Допустимо от {min} до {max}».
    Если задана одна граница — «Не меньше {min}» или «Не больше {max}».
  - Пустое поле без границ: «Нужно число».
- `select`
  - Значение — `options[].value`, подпись — `options[].label`.
  - Если значение не из `options`, в списке показывается пункт «Не выбрано»;
    после выбора значения этот пункт исчезает.
  - Ошибка: «Значение не из списка options».
- `checkbox`
  - Квадрат 18 px, отмеченный — crimson.
- `resource`
  - Подпись, справа «текущее / макс.», два поля через «/», под ними полоса
    6 px.
    Значения вводятся так же, как в `number`, дробные допустимы.
  - Полоса — доля `current / max`, по умолчанию градиент
    `#b02a40 → #ea6a7e`, трек `#282836`.
  - Пустое значение: «Нужно число в current и max».
  - `current` вне `min…max`, в том числе больше `max`:
    «Допустимо от {min} до {max}».
  - `max` меньше `min`: «Не меньше {min}» у поля «макс.».
  - При любой ошибке полоса не рисуется, под полями остаётся только текст
    ошибки.
  - Read-only: «21 / 28» плашкой, полоса цвета системы, как в режиме правки.
- `calculated`
  - Пунктирная рамка `rgba(154,143,230,.45)`, фон `rgba(154,143,230,.08)`,
    значение Geist Mono 15 px `#c9c2f7`, формула справа 10.5 px `#9a8fe6`,
    иконка `function` у подписи.
  - Знак `+3`, `−1`, `+0` только у пары «значение | модификатор».
    Одиночное `calculated`-поле, например итоговый AC, — число без знака.
  - Дробный результат округляется до двух знаков без хвостовых нулей:
    3,33; 2,5; 3.
  - Под полем «Не редактируется, пересчитывается при изменении {поле}».
    При нескольких зависимостях подписи полей идут через запятую без обрезки:
    «при изменении STR, DEX».
    Если формула состоит только из констант, подсказка — «Не редактируется»
    без продолжения.
  - Ошибка зависимости: значение «—» цвета `#8b8899`, под ним `#ea6a7e`
    «Зависит от {подпись}: исправьте значение».
  - Сбой формулы: значение «—», «Сохранить» недоступна, потому что сервер
    отвечает на такие данные ошибкой `422` и версия не создаётся.
    Деление на ноль зависит от ввода, поэтому текст называет поля:
    «Деление на ноль: измените {поля}», где поля — подписи полей-чисел формулы
    через запятую, в том числе через другие `calculated`.
    Цикл, неизвестное поле и неразбираемую формулу сервер отклоняет при
    импорте схемы, для них запасной текст «Не удалось вычислить значение».
  - Read-only: значение из снимка и формула в одной строке внутри плашки,
    для пары см. [Секции и сетка](#секции-и-сетка).

Цвет полосы `resource` выбирается по системе без ветвления в renderer:
полоса окрашивается в цвет метки системы.
Crimson для D&D 5e и по умолчанию, зелёный `#3f8f68 → #8fd4b0` для CoC,
фиолетовый `#6f63c9 → #b3aaf0` для импортированных.

### Поведение листа

`calculated`-поля пересчитываются на клиенте сразу при изменении зависимого
значения.
Формулы исполняет ограниченный expression engine, `eval()` запрещён.
Допустимые операции и функции перечислены в
[DiceBound MVP](./mvp-scope.md#dynamic-character-sheet).

Поле, значение которого отличается от последнего сохранённого, получает
границу `rgba(234,106,126,.55)`.
Для пары «характеристика + модификатор» границу `rgba(234,106,126,.35)`
получает вся пара, поле внутри отдельной границы не получает.
Пара с ошибкой — граница `rgba(234,106,126,.6)`.
Невалидное значение блокирует «Сохранить».
Сбой формулы `calculated` тоже блокирует «Сохранить»: сервер отвечает на него
ошибкой `422`.
«Отменить изменения» возвращает последнее сохранённое состояние без
подтверждения.
Версия создаётся только по нажатию «Сохранить».
В запросе сохранения клиент присылает только пользовательские значения,
значения `calculated` считает сервер.

Серверные ошибки валидации из `details[].field` показываются у полей так же,
как клиентские.

## Editable и read-only состояния

Режим листа определяется ролью пользователя и открытой страницей.

| Режим | Доска | Поля | Вкладки |
| --- | --- | --- | --- |
| Лист владельца | `SheetDnD`, `SheetCoC` | редактируемые | все три |
| `EDIT`-копия | `SheetCopy` | редактируемые | все три |
| Историческая версия | `Version` | read-only | нет |
| Получатель `VIEW` | `SheetView` | read-only | Лист, История* |
| Предпросмотр импорта | `Import` | редактируемые | нет |

«Все три» — вкладки «Лист», «История», «Доступ».
\* «История» видна, только если владелец открыл её при выдаче.

- Лист владельца — панель сохранения.
- `EDIT`-копия — баннер происхождения, своя история с v1,
  «Сохранить копию».
- Историческая версия — баннер версии, «К истории», «Восстановить эту версию».
- Получатель `VIEW` — баннер «Только просмотр», вкладки «Доступ» нет.
- Предпросмотр импорта — значения не сохраняются, панели сохранения нет,
  показывается только после успешной проверки схемы.

В read-only режиме поля выводятся плашками.
Панели сохранения в read-only режиме нет.

## Системные состояния

Доски `States` и `UIKit-States`.
Каждый экран с данными обрабатывает состояния ниже.

- Загрузка листа — скелет повторяет сетку секций, а не конкретную систему:
  шапка, вкладки, две карточки секций.
  На планшете и телефоне сетка скелета в 2 колонки, по правилам листа.
  Блоки `#1a1a22`, скругление 8 px, контейнер `aria-busy="true"` и
  `aria-label="Лист загружается"`.
- Загрузка списка — три строки-скелета вместо строк таблицы или истории,
  заголовок и кнопки страницы видны сразу.
- Ошибка загрузки (сеть или 5xx) — на месте контента иконка `alert`,
  «Не удалось загрузить данные», «Проверьте соединение и попробуйте ещё раз.»
  и кнопка «Повторить».
- 404 — иконка `lock`, «Персонаж не найден или доступ закрыт»,
  «Владелец мог удалить персонажа или отозвать ваш доступ VIEW» и кнопка
  «К списку персонажей».
  Один текст для отсутствующего и чужого персонажа.
- Ошибка сохранения (сеть или 5xx) — панель сохранения «Не удалось
  сохранить», изменения остаются, версия не создаётся, кнопка «Повторить».
- Истёкшая сессия (401) — модальное окно «Сессия завершилась» с текстом
  «Войдите снова, чтобы продолжить. После входа откроется эта же страница.» и
  primary «Войти».

Ошибки действий в модальных окнах (сеть или 5xx) выводятся блоком ошибки формы
над кнопками: «Не удалось выполнить действие. Попробуйте ещё раз.»
Окно остаётся открытым.

### Уведомления после действий

Зелёный баннер над контентом с кнопкой «Закрыть».
Баннер не исчезает сам, закрывается кнопкой или переходом на другую страницу.
Новый баннер заменяет предыдущий.

| Действие | Где | Текст |
| --- | --- | --- |
| Удаление персонажа | `/characters` | Персонаж «{имя}» удалён |
| Удаление системы | `/systems` | Система «{название}» удалена… |
| Импорт системы | `/characters/new` | Система «{название}» импортирована |
| Восстановление | вкладка «Лист» | Восстановлена версия N. Удалено версий: K |
| Выдача `VIEW` | вкладка «Доступ» | Доступ VIEW выдан {почта} |
| Выдача `EDIT` | вкладка «Доступ» | Копия передана {почта} |
| Отзыв `VIEW` | вкладка «Доступ» | Доступ {почта} отозван |

Полный текст удаления системы: «Система «{название}» удалена из списка игровых
систем.»

## Адаптивность

Основной макет — desktop шириной 1280 px.
На меньшей ширине интерфейс перестраивается, а не сжимается пропорционально.
Правила заданы для типов блоков и типов полей,
поэтому любой лист перестраивается одинаково для любой игровой системы.

- Desktop, ≥ 1024 px — доски холста шириной 1280 px.
- Планшет, 640–1023 px — доски `TCharacters`, `TSheetDnD`, `TCreate`,
  `TAccess`, `TImport`, 768 px.
- Телефон, < 640 px — доски `MLogin`, `MCharacters`, `MCreate`, `MSheetDnD`,
  `MHistory`, `MVersion`, `MAccess`, `MShareAdd`, `MImport`, `MSystems`,
  390 px.

Минимальная поддерживаемая ширина — 360 px.
Остальные экраны на планшете и телефоне собираются по тем же правилам без
отдельных макетов: профиль, пустой список, лист получателя `VIEW`, лист
Call of Cthulhu, лист `EDIT`-копии, системные состояния.

## Доступность

Интерактивные элементы реализуются настоящими `<button>`, `<a>`,
`<input>` и `<select>` с `<label>`.
Фокус обозначается обводкой 2 px `#9a8fe6` со смещением 2 px.
Ошибка поля связывается с ним через `aria-invalid` и `aria-describedby`.
Ошибки формы и баннеры ошибок имеют `role="alert"`, уведомления после
действий — `role="status"`.
Переключатель «Вход | Регистрация» — `role="tablist"` с `role="tab"`.
Панель сохранения объявляет смену статуса через `aria-live="polite"`.

Цвет не является единственным носителем смысла.
Изменённое поле помечается рамкой и счётчиком в панели сохранения.
`VIEW`-персонажи отличаются иконкой глаза, чипом и пунктирной рамкой.
Контраст текста — не ниже 4.5:1.

## Тексты интерфейса

Язык интерфейса — русский.
Названия систем и характеристик (STR, DEX, HP, AC, Sanity,
Spot Hidden) остаются как в схеме.
Формат даты — `24.09.2026 18:42`, в местном времени пользователя.
Числа согласуются со словом: «1 версия», «3 версии», «7 версий».
Кнопки называют действие или его последствие.
Тексты ошибок API показываются из поля `message`, тексты клиентской
валидации — из этого документа.

## Решения для frontend-реализации

1. Лист строится только через `Dynamic Sheet Renderer`,
   компонент поля выбирается по `field.type`.
2. Read-only режим — флаг renderer, отдельных компонентов для истории,
   `VIEW` и предпросмотра импорта нет.
3. Цвета, размеры, скругления и длительности задаются токенами из разделов
   [Цвета](#цвета), [Layout](#layout) и [Движение](#движение).
4. Числа, номера версий, даты и формулы набираются Geist Mono,
   отрицательные модификаторы — с типографским минусом.
5. `calculated`-поля пересчитываются на клиенте без `eval()`.
6. Версия создаётся только по кнопке «Сохранить».
7. Невалидное значение и сбой формулы блокируют сохранение, серверные
   ошибки валидации выводятся у полей.
8. Скелет загрузки строится по сетке секций, а не по конкретной системе.
9. Ошибки доступа и 404 не раскрывают существование аккаунта или чужого
   персонажа.
10. Защищённые маршруты проверяют сессию через `GET /auth/me`
    и передают адрес страницы на `/login`.
11. Адаптивность реализуется по правилам для типов блоков и полей,
    без макетов под конкретную систему.
12. Кнопка в процессе запроса показывает загрузку и не принимает повторное
    нажатие.

## Ограничения

> **Ограничение:** интерфейс MVP не содержит OAuth и соцвход,
> подтверждение почты, восстановление пароля, visual diff версий,
> авторов изменений, кампании, группы, роли, чат, realtime-редактирование,
> Schema Editor, визуальный конструктор систем, drag-and-drop раскладку листа,
> публичные и анонимные ссылки, приглашение незарегистрированных, аватарки,
> загрузку файлов кроме `.json`-схемы и отдельные подсистемы инвентаря и
> заклинаний.
>
> **Примечание:** адаптивная веб-версия не является мобильным приложением и
> входит в MVP.
